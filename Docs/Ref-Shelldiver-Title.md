# Shelldiver 시작 화면 분석 (2026-10-13)

출처: 사용자 녹화 `녹음 2026-10-13 102540.mp4` (유튜브 "Shelldiver Any% Speedrun" 재생 화면, 1920×1032, 52초).
방법: 브라우저 캔버스로 0.05~0.5초 간격 프레임 격자 + 부분 확대 + 픽셀 색/길이 측정.

## 0. 한 줄 결론

Shelldiver 시작 화면은 **"UI가 없다."** 화면에 있는 것은 (1) 로고 그림, (2) 흰 글자 여섯 줄, (3) 작은 삼각형 하나, 그리고 (4) 멀리는 흐리고 가까이는 선명한 **살아 있는 장면**뿐이다. 우리 화면은 반대로 **UI(나무 판자 버튼, 금색 글자, 그림자)가 장면 위에 "붙어" 있고**, 장면은 어디나 똑같이 선명하고 똑같이 채도가 높아서 눈 둘 곳이 없다. 감성 차이의 8할은 이 둘이다.

## 1. 화면 구성 (측정값, 1920 기준 → %)

| 요소 | 자리 | 크기/비고 |
|---|---|---|
| 로고 | 오른쪽 위, x 49~99%, y 11~38% | 화면 폭의 **절반**. 손글씨 워드마크 그림. 하늘색 2톤 + 흰 하이라이트 + 짙은 남색 1도트 외곽선 + 아래쪽 그림자. 왼쪽 아래에 노란 조개, 'll' 위에 구름 방울. **움직이지 않는다**(0.1초 간격 12프레임 동일) |
| 메뉴 | 왼쪽, x 3~11%, y 42~70% | 글자만. 계속 / 새 게임 / 옵션 / 크레딧 / Discord / 종료. 글자 높이 ≈ 9도트, 줄 간격 ≈ 18도트 (글자의 2배). 흰 몸통 + 짙은 남색 1도트 외곽선. 상자·밑줄·배경 없음 |
| 선택 표시 | 항목 오른쪽 | 흰 **◀ 삼각형** 하나 (외곽선 있음). 글자 색·크기는 안 변한다 |
| 커서 | 전체 | OS 화살표를 도트로 그린 **흰 화살표**(3배 크기, 외곽선). 게임 그림과 같은 도트 |
| 조작 안내 | 오른쪽 아래, x 88~98%, y 86~100% | "선택 [마우스]" "엔터 [마우스]" "뒤로 [ESC 키캡]". 키캡 아이콘이 도트 그림 |
| 버전 | 왼쪽 아래 | 작은 도트 글자 "v1.0.2…" |
| 장면 | 전체 | 왼쪽 2/3은 **빈 하늘**(메뉴 자리), 오른쪽 1/3 아래에 섬·야자수·해먹의 캐릭터. 수평선 y ≈ 62% |

핵심: **비대칭**. 로고는 오른쪽 위, 주인공은 오른쪽 아래, 왼쪽은 메뉴를 위해 비워 둔다. 우리는 술집을 정중앙에 두고 양쪽이 대칭이라 메뉴가 그림(선인장·상자)을 덮는다.

## 2. 색과 대비 — "멀리는 회색, 가까이는 원색"

측정 색 (타이틀 t=18):
- 하늘 `#478d94` (탁한 청록, 채도 낮음)
- 구름 `#999999`, `#859a97` (**회색**. 흰색이 아니다. 2톤 평면)
- 바다 `#3c8099`, 물결 하이라이트 `#548e98`
- 섬 모래 노랑, 야자 초록, 해먹 주황: **원색**
- 메뉴 글자 흰색 + 남색 외곽선, 로고 흰색/하늘색

즉 **먼 층은 회색 계열로 채도를 죽이고**, 가까운 섬과 UI만 쨍하다. 같은 게임의 인게임 장면(t=36)은 하늘이 밝은 시안, 구름이 흰색이다 → 타이틀만 일부러 흐리게 그렸다(또는 어둑한 시간대). 그래서 흰 글자와 로고가 배경에서 **떠 보인다**.

우리: 하늘 주황, 산 주황, 모래 노랑, 술집 갈색, 선인장 초록 — **전부 같은 채도**, 전부 같은 디테일(자갈·판자결·울타리 기둥). 그 위에 갈색 판자 + 금색 글자 → 배경과 명도 대비가 거의 없어 글자가 묻힌다.

## 3. 움직임 — 적고 느리다

0.1~0.2초 간격으로 확인:
- 구름: 아주 느리게 오른쪽으로 흐른다 (5초에 몇 도트)
- 바다: 물결 하이라이트가 프레임 애니메이션으로 깜빡인다
- 로고, 야자수, 메뉴: **정지**
- 시차(마우스 따라 움직임): **없음**. 카메라 고정
- 빛내림: 타이틀엔 **없음**. 인게임(t=36)에만 있고, 그것도 폭이 넓고(화면의 10~15%) 가장자리가 **부드러운** 반투명 띠 2~3개, 밝기 10% 안팎, 아주 느리게 흔들림. 도트 계단이 아니다 — 빛은 도트 규칙을 일부러 깬다

우리: 3층 시차 + 아지랑이 + 줄기 7개가 동시에 움직인다. 움직이는 게 많을수록 "화면이 바쁘다"는 인상이 되고, 시작 화면의 "쉬고 있는 세계" 느낌이 사라진다. Shelldiver 타이틀의 캐릭터는 **해먹에서 자고 있다** — 화면 전체가 "쉼"이라는 한 단어다.

## 4. 반응과 전환 — 빠르고 단단하다

| 순간 | 측정 |
|---|---|
| 옵션 → 메인 돌아올 때 | 옛 목록이 한 번에 사라지고(0.05초), 새 항목이 **위에서 아래로 하나씩** 나타난다. 항목 간 ≈ 0.05~0.1초, 6개 ≈ 0.4초 |
| 마우스 올림 | ◀ 삼각형만 나타난다. 글자 변화 없음 |
| "새 게임" 클릭 → 원형 닫힘 | **클릭한 자리(메뉴 위치)에서** 검은 원이 시작해 0.2초 만에 화면을 덮는다. 원 가장자리 딱딱함(페더 없음) |
| 검정 유지 | ≈ 1.7초 (로딩) |
| 원형 열림 | 화면 가운데에서 0.15초. 열리는 장면은 **다른 장면**(바다 위, 위아래 검은 띠 = 시네마틱) |
| 시네마틱 | 바다 위를 옆으로 이동 → 4초 뒤 "살짝 멋진 게임"(제작사) 글자가 **즉시** 나타남(페이드 없음) → 섬이 오른쪽에서 들어와 감속 → 캐릭터 착지 |
| 일시정지(ESC) | 타이틀과 **같은 배치**(로고 위, 메뉴 왼쪽, 안내 오른쪽 아래). 장면 전체에 남색 반투명 덮개. 로고는 **흰 실루엣 판**으로 바뀜 |

우리: 줌인 0.9초 + 문 0.3초 + 원형 0.45초 = 1.65초, 원 가장자리 부드러움. 느리고 물렁하다. Shelldiver는 모든 전환이 0.15~0.2초. 느린 건 로딩 검정뿐.

## 5. 도트 규칙

- 픽셀 줄 길이 히스토그램: 3, 6, 9, 15, 18, 27, 36, 48 → **1도트 = 3화면픽셀 (640×360)**. 우리는 4픽셀(480×270)이라 더 굵다. 굵은 게 나쁘진 않지만 글자는 그만큼 더 커야 비율이 맞는다.
- 글자: 몸통 9도트, 외곽선 1도트, 줄 간격 18도트. 우리 버튼 글자(24px ÷ 4 = 6도트)는 **그들의 2/3 크기**에 외곽선 대신 그림자. 작고 약하다.
- UI 선 굵기 = 그림 선 굵기 = 1도트. 상자가 없으니 "UI 도트"와 "그림 도트"가 구별되지 않고 한 세계로 보인다 (사용자 10-12 "UI와 그림이 같은 도트"의 실제 모습).

## 6. 우리 화면과의 차이 요약 (중요한 순서)

1. **UI 상자 제거.** 판자·못·그림자 버튼 → 흰 글자 + 남색 1도트 외곽선 + ◀. 글자 높이 9~10도트, 줄 간격 2배.
2. **먼 층 채도 낮추기.** 하늘·산·구름을 회색 섞인 톤으로(사용자 그림을 뒤 층만 다시 칠하거나, 뒤 띠에만 회색 반투명 덮개). 술집·선인장·모래는 그대로.
3. **구도 비대칭.** 술집을 오른쪽으로, 왼쪽 하늘을 비워 메뉴 자리로. 로고(간판 그림)는 오른쪽 위 폭 절반.
4. **로고 = 그림.** 「깡통」 글자 대신 손글씨 워드마크(2톤 + 하이라이트 + 외곽선 + 소품 하나). 이게 화면의 주인공.
5. **움직임 덜어내기.** 시차·아지랑이·빛내림 중 하나만 남기거나, 전부 지금의 1/3 세기로. 구름 하나가 느리게 흐르는 정도가 정답. 빛내림을 쓰려면 넓고 부드럽고 희미하게(도트 계단 아님).
6. **전환 빠르게.** 원형 닫힘은 클릭 지점에서 0.2초, 가장자리 딱딱하게. 줌인은 빼거나 0.3초 안에.
7. **가구.** 오른쪽 아래 조작 안내(키캡 도트), 왼쪽 아래 버전, 도트 커서. 이게 있어야 "제품"으로 보인다.
8. **메뉴 등장 스태거.** 항목이 위에서 아래로 0.05초 간격으로 뜬다.
9. **일시정지 = 타이틀 배치 재사용** + 남색 덮개 + 흰 실루엣 로고.

## 7. 우리가 이미 맞는 것

- 메뉴를 왼쪽 세로로 둔 것
- 도트 격자를 지키는 시차·아지랑이 구현 방식
- 원형 페이드가 있는 것(속도·가장자리만 다름)
